# AGENTS.md

Working brief for AI coding agent, not docs for people (README is theirs): rules, invariants, gotchas needed to change this project correctly without rediscovering them.

## Hard rules
- **whypkg never syncs or modifies system.** Only reads package state; any write betrays whole premise ("just tell me why this is here").

## Invariants and gotchas
- New distro: one `src/backend/<name>.rs` implementing `Backend` trait plus one line in `detect()`; nothing else changes. Backend parsing is pure functions.
- rpm deps are *capabilities*, not package names, mapped to packages through PROVIDES+FILENAMES; dnf and zypper share that graph (`dnf::RpmDump`), so `zypper.rs` adds only manual set, orphans and upgrades. zypper never yields `Origin::Local`: cannot tell local rpm from orphan, since its history log is root-only.
- Flatpak, cargo, pipx, uv, npm are NOT `detect()` backends: they *coexist* with system package manager, so each reads into `backend::Layer` (`flatpak.rs`, `cargo.rs`, `venv.rs` for pipx and uv, `npm.rs`) that `load::read_world` merges onto whatever `World` system backend built, each package tagged with its `Source`.
- Sources a run reads: `--only` (browser, `why`, `leaves`), else `Sources::all_but(config.skip)`; `pending` reads only `Source::System`, since nothing else reports upgrades.
- Layers never run their installer. cargo: `~/.cargo/.crates2.json` (description and `[package.metadata] runs` from `Cargo.toml` of source copy cargo keeps under `registry/src`, or of folder of `--path` install; `--git` install keeps none). pipx, uv: each tool's virtualenv (`pipx_metadata.json` or `uv-receipt.toml` names tool, every `.dist-info` is package, `Requires-Dist` edges, `REQUESTED` marks what user asked for, `RECORD` size). npm: global `node_modules` folders (`NPM_CONFIG_PREFIX`, `~/.npmrc`'s `prefix=`, node's own prefix, `/usr/local`) and every `package.json` under each global, resolved as node resolves (nearest `node_modules` up tree).
- npm and corepack in node's own global folder (`<node's prefix>/lib/node_modules`, never folder merely under prefix such as `/usr/local`) skipped as bundled. pipx tool in both new and old pipx home read from new one. Global under `/usr` (not `/usr/local`) owned by system package manager (`Backend::owners`) is system package (Arch's `typescript`), never listed twice; hence `read_world` detects backend even when `--only` leaves system's packages unread.
- Keys unique across sources: system package keeps name, flatpak its app ID, everything else `<source>:<name>` (`cargo:ripgrep`), package inside tool's virtualenv or `node_modules` `<source>:<tool>/<name>` (`pipx:httpie/requests`, plus `@<version>` when one npm global holds two versions, or two global folders hold same package). `Package.label` is name to show, read through `Package::label()`/`World::label()`; every screen and report shows labels, every `--json` `name` is key. `whypkg why <name>` explains every package whose label is that name (every installer's copy), falls back to key when nothing has that label.
- `World.uses`/`used_by` link package to system packages it loads or runs on. Each layer lists `needs`: canonical path of library a cargo binary's ELF `DT_NEEDED` names, placed through `ldconfig -p` in `backend/elf.rs` without running binary as `ldd` would; each program crate's manifest lists under `[package.metadata] runs`, found on `PATH`, since program started at run time leaves no trace in binary; Python a virtualenv's `bin/python` points at; node on `PATH`. `read_world` asks `Backend::owners` once for all of them.
- `uses`/`used_by` kept OUT of `deps`/`rdeps` on purpose: `bfs_root`, `rdep_count`, `pending`'s system-lib rule and "why is this here" must follow only edges an installer recorded, else library apt pulled in for something else reads as "pulled in by" cargo tool. Shown as `uses`/`used by` in `why`, as `uses it`/`uses` rows in dossier lists (`World::needed_by_all`/`depends_on_all`) and graph, as "but X still uses it" warning in `leaves`.
- Flatpak keyed by application ID (`im.riot.Riot`), because that is what you type to remove one; human name goes first in `description` ("Element - ..."). Browser `/` filter matches label + key + description + `details`, only reason such packages are findable by real name; same mechanism finds apt's `code` by "visual studio" (long description) and cargo crate by its binary (`details` holds `binaries: rg`).
- `Package.origin` (`Repo`/`Local`/`Orphaned`) answers "did I sideload this?": apt combines `[installed,local]` tag from `apt list --installed` with scan of `/var/log/apt/history.log*` for `.deb` installs; pacman uses `pacman -Qm` (foreign); dnf uses `from_repo` (`@commandline` = local, `@System` = orphaned). Local vs orphaned split best-effort, since history logs rotate.
- Graph view (`src/tui/graph.rs`, `ctrl-g`) is ratatui `Canvas` with braille markers, so works in every terminal incl. tmux and over ssh; never use image protocol (kitty/sixel), tmux breaks them. Layout tests in `graph.rs` encode its visual rules (no two labels on one row, arcs off centre line): change that fails them is real visual bug.
- Rust ignores `SIGPIPE`, so `whypkg pending --quick | head` panics without `restore_sigpipe()` in `main.rs`, which resets it to default on unix. Never remove it; keep report output on plain `println!`.
- `capture()` forces `LC_ALL=C`, so labels, dates, sizes parse whatever user's locale; never read tool output without it.
- Query whose failure would read as empty answer (`unneeded()`, zypper's tables) goes through `capture_checked`, which turns non-zero exit into error quoting tool's stderr; `capture` ignores exit code because `pacman -Qm` and friends exit 1 for "none".
- `whypkg leaves` takes unneeded group from `Backend::unneeded()`, package manager's own autoremove answer, never from graph: graph has no Suggests, virtual packages or alternatives, so calls packages apt keeps "unneeded". Flatpak has no read-only way to ask, so its runtimes never appear there. Queried only by `leaves`, so browser startup does not pay for it.
- `--json` output (`why`, `leaves`, `pending`) promises fixed field names and reason words in `--help`; renaming one is breaking change.
- Upgradables reflect user's last sync (`pacman -Qu`, `apt list --upgradable`, `dnf repoquery --upgrades --cacheonly`), so only as fresh as last `apt update`; whypkg must not sync to refresh them.
- Settings box (`o`) writes `~/.config/whypkg/config.toml` (`skip = [...]`) with `toml_edit`, so person's comments and unknown keys survive.

## Build / lint / test
- `cargo build --release`, binary at `target/release/whypkg`.
- Other distros: build inside `archlinux`/`fedora`/`opensuse/tumbleweed`/`cachyos/cachyos` podman containers (`CARGO_TARGET_DIR=/tmp/...`), regenerate fixtures from there.
- New layout or algorithm test: mutation-check it (reintroduce bug, confirm test fails), since too-loose threshold silently passes.
- Backend parsers tested against captured real output in `tests/fixtures/` via `include_str!`; synthetic worlds from test-only `World::from_edges()` (`src/model.rs`). Untested: npm's folder walk, `ldconfig` lookups, browser's keys.
- Run: `whypkg` (browse), `whypkg --upgradable`, `whypkg --only system,cargo`, `whypkg why <PKG>... [--json] [--only S]`, `whypkg pending [--quick|--kernel|--apps|--auto|--sizes|--json]`, `whypkg leaves [--quick|--json] [--only S]`. Point `XDG_CONFIG_HOME` at scratch folder before trying settings box (`o`), so real settings file is never written.
- README screenshots live in `readme-assets/` (excluded from crate), referenced by absolute GitLab raw URLs, because relative paths do not render reliably on crates.io; push them before publishing or URLs 404. Fetched live, so replacing one needs no release: push file, every rendered README updates.
- **Never capture README asset by hand.** Every picture comes out of `demo/` rig, source of assets as build script is source of binary. `demo/render.sh` renders every tape (or named ones) in container, so machine needs only podman or docker. Image is `demo/Dockerfile`: vhs's own image pinned by digest, apt pointed at `snapshot.debian.org` at date in its `SNAPSHOT` arg (nothing installed on top yet). Each tape runs in own container, as your user (`--userns=keep-id`, or docker's `--user`) so images stay yours and prompt ends in `$`, no network, staging, recording from repo root, tearing down with `demo/stage.sh down`. UI change means rerunning tape, never rearranging terminal and cropping. Rendering deletes and rebuilds `demo/home/` (gitignored), writes nowhere else; `demo/` excluded from crate.
- Rig films *invented* Debian workstation, never this machine: `demo/fixtures/` holds package data captured once from throwaway `debian:sid` container plus handful of hand-written packages (sideloaded `code`, orphaned `libssl1.1`, a kernel), and `cargo.tsv`, `python-tools.tsv`, `npm.tsv` for other installers. `stage.sh` turns it into shim `apt`/`apt-mark`/`dpkg-query`/`flatpak` on `PATH`, a `/var/log` it can bind-mount, and files cargo, pipx, uv, npm keep (`.cargo/.crates2.json` with each binary a copy of `true` grown with `truncate`; virtualenv per tool whose `bin/python` points at stage's `usr/bin/python3.14`; `bin/node` so node's prefix, and so globals, are stage's home); `enter.sh` runs release binary against that under `bwrap`. `dpkg-query -S` shim places files by name (`libc.so.6`→libc6, `libgcc_s.so.1`→libgcc-s1, `python3.14`→python3.14-minimal, `node`→nodejs), so `uses` links come out same wherever rendering machine keeps its libraries. Only `demo/capture.sh` needs podman and network, only when demo world should hold different packages. That indirection is also why pictures render identically on machine with no apt.
- Anything whypkg reads *directly* must be masked in `enter.sh`, else real machine leaks into frame: `/var/log` and `/var/log/apt` bound to stage; `/var/lib/flatpak` is tmpfs because flatpak install dates come from deploy directory's mtime and system path is checked before per-user one; `/usr/local/lib/node_modules` is tmpfs (when it exists) because npm's globals are read there whatever node's prefix. Everything else layers read is under `HOME` (the stage), and environment is cleared, so `CARGO_HOME`, `PIPX_HOME`, `UV_TOOL_DIR`, `NPM_CONFIG_PREFIX`, `XDG_*` cannot point anywhere real. Check every new direct read.
- In render.sh's container bwrap cannot run unprivileged, so container masks them itself: empty tmpfs on `/var/log` (with podman's `notmpcopyup`, since image is Debian and podman would otherwise copy its real apt history into it) that render.sh fills from stage's logs, and empty tmpfs on `/var/lib/flatpak` and `/usr/local/lib/node_modules`. `enter.sh` under `DEMO_MASKS=container` checks three mounts, that two folders are empty, compares logs with stage's, refusing on any difference, then opens same shell under `env -i` instead of bwrap.
- Tape gotchas: VHS reads `Ctrl+G` as Ctrl+Shift+G, which browser does not bind, so tape ctrl keys lowercase (`Ctrl+g`); graph opens with centre node selected and centre is column of one, so tape must press Left/Right before Up/Down does anything; VHS's parser rejects paths with digits in directory name, so tape paths stay inside repo. `shots.tape` makes `browse`, `search` (`/Element`, filter while typed), `dossier` (`/libllvm`, `↵` twice), `graph` (`ctrl-g`) and `uses` (`/nodejs`, npm globals that run on it); `report.tape` makes `pending`.
- Frame 1180x620 (112x28) for browser, 720x520 for report, because browser row is 106 columns wide before its description and report is 62: wider frame is dead space, and forge scales over-wide picture down until unreadable.

## Overview
Layout:
- `src/main.rs`: clap `Cmd` enum and dispatch match, nothing else.
- `src/commands/<verb>.rs`: one file per command: `browse` reads world, hands it to interface; `why` prints dossier; `pending` is upgrade report; `leaves` lists what is worth second look; `selfcmd` is `whypkg self`. `commands/mod.rs` picks sources (`--only` or settings file), loads world for a report.
- `src/tui/` is browser: `mod.rs` owns `App`, tabs, each tab's dossier and way back, `/` filter, background re-read, terminal; `input.rs` every key; `line_edit.rs` shell-line editing of `/` query; `render.rs` tab line, list, dossier, status line, footer, help, settings box; `options.rs` settings box state; `boot.rs` loading wordmark; `graph.rs` braille dependency graph; `widgets.rs` footer words and `key_footer`, house box, key rows, scrollbar.
- Top-level domain modules: `backend/` (one file per package manager, plus layers and `elf.rs`), `load` (`Sources`, `Progress`, `read_world`), `config` (settings file), `engine` (distro-agnostic `bfs_root` trace), `model` (`World`).

`whypkg` ("why is that package here? know it now"): fast, cross-distro Rust CLI investigating installed packages: did you install it or did something pull it in, when, alongside what, what needs it, what it needs. Rewrite of original bash `apt-why`/`apt-pending` scripts (kept in `legacy/`, excluded from published crate). One distro-agnostic engine (`src/engine.rs`, `bfs_root` as "why is this here" origin trace) feeds interactive ratatui browser (default, tab per installer, `ctrl-g` braille dependency-graph view) and three reports: `why` prints dossier, `pending` classifies upgradable packages by why they are present, `leaves` lists what autoremove would take plus sideloaded and orphaned packages. Backends: apt, pacman, dnf, zypper, plus flatpak, cargo, pipx, uv, npm layered on any of them, with `uses` links from those to system packages they load or run on. Crate and binary both `whypkg`, on crates.io, AGPL-3.0-only.
